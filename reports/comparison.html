# 상용 커뮤니티 화면 비교와 이번 반영

작성·재확인: 2026-10-05. 요구 P3-02, P3-04, P4-05, P5-02, P5-03, P7-01. 완료 기준: 기존 조사 근거를 구분해 재검토하고, 구성 전환과 이미지 표시 설정을 구현하며, 기존 메모·저장 흐름을 유지한다. 비공개 실험 범위다.

## 이미지 방식: 화면 추정과 실제 관찰의 분리

2026-10-05 공개 페이지의 현재 DOM도 확인했다. 표본은 로그인하지 않은 1280px 브라우저에서 관찰한 일부 이미지다. 모바일 URL이라고 390px 측정으로 표기하지 않는다. 개인 글 내용·사용자 식별자·이미지 전체 URL은 보고서에 옮기지 않았다.

| 페이지 / 표본 | DOM에서 실제 확인 | 이 관찰로 확정할 수 없는 것 |
|---|---|---|
| Blind 한국 홈, 첫 12개 이미지 | 주제 아이콘은 표시 24×24, 원본 200×200; width/height 24 지정. 이 표본에 srcset 없음, loading/decoding 기본 auto, picture 0개 | 전체 사이트의 CDN 변환 규칙, 실제 코덱, 네트워크 전송량, 사진 게시물 전체 정책 |
| Naver Cafe 모바일 홈 `/ca-fe/`, 8개 이미지 | 표본은 loading=lazy, srcset 없음. 프로필 77×77→24×24 (`type=c77_77`), 카드 360×240→약299×199 (`type=ff360_240`), 작은 사진 200×200→68×68 (`type=ff200_200`). HTML width/height 속성은 없음 | CSS 공간 예약이 없다는 결론, 서버 압축 구현, 전체 서비스의 지연 로딩 정책, LCP 성능 |

따라서 ‘상용 사이트가 이렇게 하므로 무조건 최선’이라고 복제하지 않는다. 작은 표시 크기에는 작은 변환본을 제공하는 원칙을 채택하고, 우리 UI에서는 실제 슬롯 폭과 화면 배율에 맞게 브라우저가 선택하도록 `picture` + `srcset` + `sizes`를 사용한다. [MDN img](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img), [MDN picture](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/picture).

## 구현한 선택지

상단 **구성 비교**에서 화살표나 미니어처 버튼으로 네 구성을 넘긴다. 같은 콘텐츠로 비교하므로 배치의 차이를 알아보기 쉽다. 기존 A/B/C 디자인과 색상을 유지하면서 구성만 바꾼다.

| 구성 | 도입 / 목록 / 설명 | 사진 / 표면 / 간격 |
|---|---|---|
| 제목 중심 게시판 | 제목만 / 한 열 / 설명 숨김 | 사진 없음 / 구분선 / 85% |
| 썸네일 목록 | 간결한 도입 / 한 열 / 설명 두 줄 | 작은 정사각 사진 / 구분선 / 95% |
| 요약 중심 카드 | 간결한 도입 / 한 열 / 전체 설명 | 사진 없음 / 카드 면 / 110% |
| 이미지 중심 카드 | 간결한 도입 / 두 열 / 설명 두 줄 | 16:9 사진 / 카드 면 / 110% |

색상·모양에서 도입부, 설명 길이, 면/구분선, 사진 없음/썸네일/커버, 1:1·4:3·16:9 비율, 채우기/전체 보기, 위·중앙·아래 초점을 각각 조절할 수 있다. 기존 본문 크기·여백·폭·라운드·색상 설정과 조합한다. 제목은 화면에서 감추지 않는다. 설정은 메모와 함께 이름 저장·다른 이름 저장·JSON·HTML에 포함된다. 새 설정이 없는 이전 JSON은 사진 없음 등 기존 기본값으로 읽는다.

## 이미지 자산과 처리

두 사진은 별도로 출처와 CC0를 확인했다. 교육은 [Trey Jones의 빈 책 사진](https://commons.wikimedia.org/wiki/File:Blank_books_stacked_on_a_table.jpg), 생활은 [Siddharth Patil의 Boyd Park 산책로](https://commons.wikimedia.org/wiki/File:Boyd_Park_path.jpg)다. [CC0 조건](https://creativecommons.org/publicdomain/zero/1.0/) 아래 상업적 재사용이 가능한 사진이다. 특정 기관의 공식 사진이나 사용자 경험 사진으로 표시하지 않는다.

원본은 배포에 포함하지 않고, 160·320·640·1200px 너비의 AVIF/WebP/JPEG 24개를 생성했다. 회전 적용 후 새 RGB 이미지로 재인코딩하여 EXIF/GPS·설명·프로필을 옮기지 않는다. 파일별 치수·바이트·SHA-256와 출처를 manifest에 기록했다. CSS는 표시 비율을 예약하고 전체 사진/자르기·초점 조절을 제공한다. 실제 사진 내용은 제목과 별개 장식이므로 중복 낭독하지 않는다.

| 사진 | 원본 파일 | 160px WebP | 640px WebP |
|---|---:|---:|---:|
| 책 | 478,282 B / 1200×1200 | 2,280 B | 33,418 B |
| 산책로 | 18,499,827 B / 6382×2696 | 1,908 B | 19,862 B |

이는 **리사이즈와 재인코딩을 합한 결과**이며 같은 해상도의 코덱 우열 비교가 아니다. DPR·슬롯 폭에 따라 더 큰 파일을 선택할 수 있고, 한번 받은 큰 파일은 브라우저가 재사용할 수 있다. 실사용 LCP/CLS 개선량은 측정하지 않았으므로 수치로 주장하지 않는다.

사진 표시를 끈 새 페이지에서는 이미지 요소를 만들지 않는다. 사진을 켤 때 화면 안 항목은 eager, 밖은 lazy로 만들고 decoding=async를 지정했다. 브라우저는 화면에 닿기 전에 lazy 이미지를 가져올 수 있다. 주요 첫 화면 LCP 이미지를 무조건 lazy로 만드는 방식은 피한다. [브라우저 지연 로딩](https://web.dev/articles/browser-level-image-lazy-loading), [LCP 최적화](https://web.dev/articles/optimize-lcp).

해시 파일명과 미디어 전용 private immutable 캐시 정책을 생성한다. 실제 호스트 헤더 적용 여부는 별도 운영 점검 사항이다. 사진 내보내기용 데이터는 최초 페이지 JS에 넣지 않고 HTML 저장 시 별도 같은 출처 파일에서 읽어, 640px JPEG를 독립 HTML 안에 포함한다. 사진 저작자·출처·CC0와 기존 MIT 고지도 파일에 포함한다. 기본 생성물·일반 공개 프로젝션에는 이 실험 편집용 미디어를 넣지 않는다.

## 남는 범위

실제 회원 업로드 처리, 악성 파일 검사, 동의·보존기간, 서버 저장·접근 통제는 이번 정적 실험이 제공하는 기능이 아니다. 사진 메타데이터 제거가 개인정보보호법상 면책을 보장하지 않는다. 독립 HTML 파일의 브라우저 실행은 앞선 환경 정책 제한 때문에 미검증이며, 다운로드 파일의 구조·스크립트 구문·이미지 포함과 호스팅된 편집기를 검증한다. 공개 회원 서비스 출시는 별도 승인·검증 범위로 유지한다.
