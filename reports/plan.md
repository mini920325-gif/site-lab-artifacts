# 커뮤니티 웹페이지 계획 · 2026-10-05

행정사무소의 목적을 담으면서 전직·취업·창업·교육·생활·보훈의 질문과 대화가 쌓이는 커뮤니티를 만든다. 대상은 20~50대이며 주 이용자는 2030이다. 이번 결과는 기존 조사와 구현을 연결한 비공개 체험판이다. 최종 이름과 공개 운영 정책은 아직 결정하지 않았다.

## 조사에서 이번 설계로

기준은 기존 7개 기둥·32개 요구·37개 근거·7개 정정이다. 에이전트의 설계 제안은 사용자 결정과 구분했다. 디자인 토론 18개 글, 목적 인터뷰 13개 글, 이름 토론 3개 글이 원본으로 남아 있다. 아래는 실제 제안·시도·철회와 이번 선택의 관계다.

| 원래 제안과 실제 확인 | 이번 구현 선택 | 남는 검증 |
| --- | --- | --- |
| engine의 검색대: 제목·본문 미리보기와 검색. 실제 스케치의 작성 폼은 본문 옆이 아니라 하단에 있었음 | 검색어 없이도 바로 읽는 제목 중심 목록. 검색은 상단에 유지 | 사람이 검색어를 떠올리지 못해도 원하는 글을 찾는가 |
| engine의 열린 대화와 docs의 대화 펼침: 같은 축의 두 배치라고 정정. 최초 글을 크게 펼치면 다른 관심사가 묻힐 수 있음 | 전체 주제 목록을 첫 화면에 두고 글 전문은 선택 후 열기 | 첫 글 편집 없이도 대화 참여가 이어지는가 |
| docs의 작업대: 기본 세 칸을 철회하고 자료·초안을 선택형으로 축소. 정적 검사 통과와 게시 기능 완성은 다름 | 상황 필터는 접어서 선택적으로 사용. 일반 글쓰기에 근거·인용 요구 없음. 기존 초안 복귀 유지 | 읽던 글을 참고하면서 작성할 때 별도 작업대가 실제 도움이 되는가 |
| 주제 AND 지도: 기존 fixture의 10개 조합이 모두 빈 결과여서 중심 행동을 철회 | 여섯 주제는 각각 선택. 교집합 지도를 첫 행동으로 채택하지 않음 | 실제 글이 충분히 쌓인 뒤 복수 주제의 필요 검토 |
| Cursor Grok: 문장 붙이기 스케치와 여섯 화면 조건 측정. 필수 인용·비회원 기본 입력 노출은 일반 작성 흐름으로 채택하지 않겠다고 수정 | 로그인 없이 글과 댓글 읽기. 작성 의사를 밝힌 후 체험 로그인. 인용 없이 질문·경험 작성 | 선택 인용을 도입할 때 읽기와 게시가 혼동되지 않는가 |
| Grok Bot: 390px 조작 크기 측정. 방문자 과제·사람 관찰은 없었으며 24px/44px 수치를 직접 비교할 수 없다고 정정 | 주요 버튼의 최소 높이는 2.75rem. 글자 200%와 390/768/1280px에서 다시 검사 | 실제 터치·키보드 이용자의 과제 수행 확인 |

이 관찰들은 실제 수요나 재방문 효과를 입증하지 않는다. 목록 중심 배치는 이번 구현의 출발점이며 최종 채택 결과가 아니다. 과거 스케치와 철회 기록은 그대로 보존한다.

## 페이지와 방문자가 끝낼 일

| 화면 | 방문자의 과제 | 구현 범위 |
| --- | --- | --- |
| 커뮤니티 목록 | 제목·미리보기로 글 선택, 주제·검색·댓글 여부·상황으로 좁히기 | 여섯 주제, 정렬, 페이지 이동, 빈 결과와 검색 해제 |
| 글 상세 | 전문·댓글을 읽고 이전 목록으로 돌아오기 | 목록의 검색·필터·페이지·스크롤 맥락, 직접 주소와 브라우저 이력 유지 |
| 글쓰기 | 질문이나 경험을 자유롭게 작성 | 체험 로그인 후 작성·본인 수정. 제목 100자, 내용 5,000자. 초안은 현재 화면에 유지 |
| 댓글·답글 | 읽은 글에 반응하고 본인 내용을 관리 | 댓글 1,000자, 수정·삭제. 부모 댓글을 삭제해도 다른 회원의 답글 유지 |
| 내 활동 | 내 글과 저장한 글 다시 찾기 | 두 체험 계정의 작성 권한·저장 목록 분리 |
| 자료실 | 공식 안내와 회원의 경험을 구분 | 기존 공식 원문 진입점을 계승. 최신 소식·법률 판단을 새로 만들어 채우지 않음 |
| 소개·도움말·정책 | 운영 범위와 개인정보·저장 한계 확인 | 익명 공개와 체험 저장 안내, 기존 정책 초안 유지 |
| 운영·디자인 체험 | 설정 미리보기와 신고 상태를 확인 | 기존 골격 계승. 실제 서버 권한과 신고 전달은 연결 전 |

## 화면 방향

이번 세션에서 Clien 자유게시판과 FMKorea 자유게시판을 실제로 열어 목록 행의 간격, 제목·메타 정렬, 안쪽 여백을 확인했다. 이전 자료를 읽은 것과 이번 직접 관찰을 구분한다. 현재 스타일에서 상속 규칙이 목록의 좌우 패딩을 0으로 덮는 결함을 찾아 바로잡았다. 상용 사이트의 밀도와 정렬 원칙을 참고하되 광고 영역이나 작은 본문 글씨를 그대로 복제하지 않는다. 방문 관찰은 과제 성공이나 실제 이용 수요를 입증하지 않는다.

사용자의 최신 요청에 따라 상단 ‘디자인 비교’에서 **목록 형태·여백·글꼴·색**을 각각 이전/다음 화살표로 넘긴다. 각 축은 세 옵션이며, 제목과 한 줄·간결한 게시판·넓은 미리보기는 정보 배치와 본문 노출 깊이가 다르다. 변경은 즉시 미리보기, ‘이 조합 적용’은 현재 브라우저의 표시 설정 저장, ‘취소’는 적용 전 조합 복귀, ‘기본값 미리보기’는 별도 동작이다. 검색·주제·정렬·페이지·글 주소·입력 초안·작성 권한은 이 표시 조합과 독립적으로 유지한다.

짙은 잉크색 글자, 선명한 블루 조작, 흰 목록과 얇은 구분선으로 글의 위계를 만든다. 카드 타일이나 홍보 문구가 본문을 밀어내지 않게 한다. 제목과 짧은 미리보기를 행으로 읽고, 세부 필터는 필요할 때 연다. 브랜드는 중립적인 ‘커뮤니티’와 ‘이름 검토 중’ 표시로 둔다.

PC에서는 넓은 글 목록과 좁은 안내 영역을 나누고, 태블릿·모바일에서는 읽는 면을 먼저 배치한다. 본문은 1rem, 반복 조작은 기본 14px 이상으로 사용하며 확대 시 줄바꿈을 허용한다. 모든 주제가 검색·주소·작성·목록에서 같은 식별자를 사용한다. 내용·권한·주소의 계약과 시각 설정을 구분해 이후 테마 변경 시 기능을 이어간다.

## 단계별 구현과 운영 준비

1. **이번 비공개 체험판:** 기존 중단 구현을 독립 사본에서 계승. 목록·필터·본문·작성·댓글·본인 관리의 동선을 다듬고 기능·화면·제품·반영 검토를 통과한 버전만 배포한다. 기존 세 원형의 결함과 미연결 상태는 별도 기록으로 유지한다.
2. **사람의 과제 관찰:** 찾기→읽기→복귀, 자발적 작성→댓글→본인 관리 과제를 실제 이용자에게 확인한다. 목록·열린 대화·선택 작업대의 이점은 그 결과로 판단한다.
3. **운영 연결:** 실제 로그인 공급자, 연령별 가입 절차, 익명 표시와 내부 신원, 영속 저장, 서버 소유권·운영자 권한, 삭제 요청 수신을 결정하고 구현한다. 추가 결제와 실자료 업로드는 이번 작업에 포함하지 않는다.
4. **자료와 응답 운영:** 콘텐츠 수급·검수·댓글 응답 책임을 정한다. RSS는 공식 출처·발행일·원문·이용 조건·검수 상태를 갖추며 회원글과 분리한다. 사무소 상담과 법령·AI 상담 분기는 기존 수리와 자료를 찾아 이어간다.
5. **지속 운영과 수익:** 무료 이용 방향을 유지하고 광고·제휴·도움주기 배너를 별도로 검토한다. 운영자만 리다이렉트를 관리하고 광고를 명확히 표시한다. 방문량·요청량을 가정한 호스팅·인증·저장 비용 상한, 결제 주기, 캐시·오류 감시·복구 절차를 정한 후 공개 운영으로 전환한다.

## 이번 완료 기준과 한계

- 비회원 읽기와 선택적 로그인 작성이 구분된다.
- 두 체험 계정에서 본인 수정·삭제·저장 상태가 섞이지 않는다.
- 검색·주제·정렬·페이지·직접 주소·뒤로 가기·빈 결과·없는 글이 작동한다.
- 모바일 390px, 태블릿 768px, PC 1280px에서 기본 글자와 200% 글자로 목록·상세·작성·대화상자를 확인한다.
- 합성 글에는 구성 예시 표시를 유지하고 가짜 조회·활동·후속 경험을 만들지 않는다.
- 정확한 코드 버전과 기능·화면 증거를 남기고 세 독립 역할의 검토 후 기존 소유자 비공개 Site에 반영한다.

입력과 체험 계정은 현재 페이지 메모리에만 있으며 새로고침하면 초기화된다. 체험 로그인은 실인증이 아니고, 화면의 소유권 분리는 서버 접근 제어가 아니다. 실제 회원 운영·DB·RSS 수집·광고·상담 API·자동 갱신·공개 전환은 이 문서의 후속 계획이다.
